## 3. M1 — 분석 대기에서 준비 완료까지

**사전 조건:** 격리된 로컬 환경, 신규 테스트 지원자, 제출 가능한 서류, 유효한 기술 리포트 없음, 로컬 AI 이벤트 처리가 가능한 구성. 실제 이벤트 처리가 불가능하면 M1은 미실행이며 DTO 단위 테스트로 대체 통과하지 않는다.

1. 제출 성공 시각과 지원자를 구분할 테스트 식별자를 기록한다.
2. 같은 지원자로 상태 API를 즉시 조회하고 5초 간격으로 응답 시각·syncStatus·analysisCompleted를 기록한다.
3. 분석 대기 구간의 false와 동기화 완료 후 `COMPLETED + false` 조합을 관찰한다. 분석이 너무 빨라 구간을 놓쳤다면 관찰 실패로 기록하고 통과로 추정하지 않는다.
4. 리포트 `job/role`이 저장·커밋된 뒤 시작한 조회에서 true를 확인한다. 조회 시점에 보이는 DB 데이터 또는 처리 완료의 증거를 남긴다. 수신 로그만으로 대체하지 않는다.
5. 프론트가 준비되어 있다면 true 수신 후 폴링 중단과 사용자 클릭 후 면접 시작을 확인한다. 그렇지 않으면 API 동작만 확인했다고 기록한다.

**통과:** 미완료 false와 커밋 이후 true가 관찰되고 조회 자체가 재분석 이벤트를 발행하지 않는다. 실제 UI 종료 여부는 M3으로 판정한다.

## 4. M2 — 업무 오류의 연결 한정 전달

**사전 조건:** 유효한 테스트 지원자 인증, 재응시 제한에 걸리지 않고 분석이 미완료인 지원자, `/ws`에 연결 가능한 로컬 서버. 연결 A·B는 같은 사용자로 인증한다. 프레임 기록에서 토큰은 제외한다.

1. A·B 각각 STOMP CONNECT 후 `/user/queue/interviews`를 구독한다. 구독 등록이 끝난 뒤 요청한다.
2. A에서만 `/app/interviews/start`에 `{"interview_type":"TECHNICAL"}`을 보낸다.
3. A의 구독 콜백에서 STOMP `MESSAGE`를 받는다. 본문은 `type=ERROR`, `error_code=APPLICANT_ANALYSIS_NOT_COMPLETED`, 기본 사용자 메시지여야 한다. 다른 세션·질문 필드는 null이다.
4. B에는 같은 업무 오류가 전달되지 않는지 두 연결의 기록으로 확인한다. A 오류 수신 전후의 관찰 구간과 프레임 시각을 남긴다. 연결 종료를 정상 업무 오류 수신으로 처리하지 않는다.
5. 분석 완료된 테스트 상태에서 사용자 요청으로 면접을 시작하고 `SESSION_STARTED`와 기존 질문 흐름을 확인한다.
6. 자신이 소유한 활성 면접에 존재하지 않는 질문 코드를 담은 유효한 답변 요청을 보내 `BAD_REQUEST`와 업무 메시지가 C3으로 전달되는지 확인한다. 필수 필드 누락으로 Bean Validation 오류를 유발하는 테스트와 구분한다.

**통과:** 오류 발생 연결만 해당 오류를 받고, 기존 정상 흐름을 유지한다. A·B가 모두 오류를 받으면 `broadcast=false` 계약 실패다. 단위 테스트 통과만으로 M2를 완료하지 않는다.

## 5. M3 — 프론트 상태·로딩·폴링

프론트 구현 경로는 현재 확인하지 않았다. 실제 경로와 테스트 실행 명령을 확인한 후 아래 시나리오를 기존 프론트 테스트 환경 또는 브라우저에서 수행하고 증거를 기록한다. 타이머·늦은 응답은 가능하면 가짜 타이머와 응답 제어로 검증한다.

| 시나리오 | 기대 결과 |
| --- | --- |
| 제출 직후 false, 이후 true | 즉시 조회·시작 비활성·분석 중, 5초 폴링, true 후 중단 |
| HTTP 응답이 5초보다 늦음 | 두 번째 요청 중첩 없음 |
| 화면 이탈·로그아웃 중 요청 완료 | 타이머 정리, 늦은 응답으로 화면/버튼 갱신 없음 |
| 미제출 또는 동기화 FAILED | 기존 제출/재제출 안내, 분석 폴링 중단 |
| 필드 누락 또는 boolean이 아닌 값 | 완료로 간주하지 않음, 상태 확인 불가 안내, 시작 비활성 |
| 일시적 조회 실패 | 시작 비활성·실패 안내, 활성 대기 화면이면 같은 5초 주기로 재조회 |
| 인증 실패 | 기존 인증 처리, 폴링 중단 |
| 분석 미완료 ERROR | 시작 로딩 해제·메시지 표시·준비 재조회, 자동 시작 전송 없음 |
| 다른 업무 ERROR | 요청 로딩 해제·메시지 표시, 무조건 분석 중으로 전이하지 않음 |
| true이나 재응시 제한에 걸림 | 기존 제한 유지 |
| CONNECT 또는 재연결 성공 | 구독 복원, 사용자 동작 없이 면접 시작 전송 없음 |

M3의 실패·누락은 사용자 흐름 전체의 완료를 막는다. 프론트 작업이 아직 없으면 백엔드 완료와 별도로 미실행 상태를 보고한다.

## 6. D1 — API 문서 계약 검토

- 8장에 `ERROR`가 있고 11장에 JSON·코드·범위·연결 한정 설명이 있다.
- 9·12장의 상태 설명·예제가 `analysisCompleted`와 오류 분기를 반영한다.
- `onConnect` 자동 시작이 제거되고 사용자 시작 동작이 구분된다.
- STOMP `ERROR` 프레임 처리만으로 애플리케이션 오류 처리를 대체하지 않는다.
- 새로운 JSON 예시가 파싱 가능하고 실제 DTO 계약과 일치한다.
