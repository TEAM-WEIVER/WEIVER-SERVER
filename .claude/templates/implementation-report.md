# 구현 판단·코드 이해 보고서 템플릿

> 보고서 파일은 커밋하지 않는다. 작업 중에는 이 형식으로 정리하고, 팀원과 리뷰어가 볼 핵심(1~3절 요약)은
> PR 본문 `📚 구현 보고`에, 검증 결과는 `✅ 검증 결과`에 옮겨 적는다.
> 구현자는 1·2·3·4절을 쓴다. 5절은 리뷰어(읽기 전용)가 출력한 `보고서 대조` 표를 구현자가 옮겨 적는다.
> 모든 내용은 한국어로 쓴다.

## 작성 기준

**보고 수준을 먼저 정한다.** 주요 구현 결정에 설명을 집중하고, 사소한 변경은 짧게 쓴다.

| 수준 | 해당하는 변경 | 쓰는 절 |
| --- | --- | --- |
| 짧은 보고 | 설정 값·문구·오타 수정, 기존 패턴을 그대로 반복하는 변경, 테스트만 추가 | 맨 아래 "짧은 보고" 양식만 |
| 전체 보고 | 새 클래스·엔티티·API·이벤트, 계층·컨텍스트 경계나 트랜잭션에 영향, 대안이 둘 이상인 결정 | 1~5절 전부 |

**결정의 출처를 구분한다.**

- **AI 제안**: AI가 제안했고 아직 사용자가 확정하지 않은 것.
- **사용자 결정**: 사용자가 직접 고르거나 승인한 것. 사용자가 말한 이유를 그대로 적는다.
- **승인된 범위 안의 구현 판단**: Issue·명세·사용자 지시로 이미 허용된 범위 안에서 구현자가 정한 것.
- **명세 기재**: 명세·계획 문서에 적혀 있지만 누가 언제 승인했는지 기록을 찾지 못한 것. 공개 API·스키마처럼
  승인 대상이면 구현 전에 사용자 결정으로 바꿔 받는다.

**검증 상태는 넷 중 하나로만 적는다.** 통과 / 실패 / 미실행 / 환경 차단.
미실행·환경 차단을 통과로 적지 않는다. 상태마다 실행한 명령과 결과(또는 실행하지 못한 이유)를 함께 적는다.

**코드 위치는 `파일경로:줄번호`로 적는다.** 리뷰어가 같은 위치를 열어 대조할 수 있어야 한다.

## 4. 완료 상태

- [ ] 구현 완료 — 계획한 코드 변경이 끝났다.
- [ ] 검증 완료 — 필수 검증을 모두 실행했고 통과했다. 미실행·환경 차단 항목이 있으면 체크하지 않는다.
- [ ] 설명 전달 완료 — 이 보고서와 PR에 판단 근거와 검증 결과를 기록했다.

## 5. 리뷰 대조 (리뷰어 출력을 구현자가 옮겨 적음)

리뷰어는 파일을 고치지 않으므로, 리뷰어 출력의 `보고서 대조` 표를 구현자가 그대로 옮기고 리뷰 모드·기준 커밋을 적는다.
리뷰어는 보고서의 주장을 실제 코드와 검증 증거에 대조하고, 코드나 증거를 직접 열어 보지 않은 주장은 "확인 불가"로 판정한다.
지적을 반영했으면 상태를 "리뷰 완료"로 바꾸고, 반영하지 않은 지적은 이유를 3절 "남은 위험"에 적는다.

- 리뷰 모드 / 기준 커밋:

| 보고서의 주장 | 확인한 코드·증거 | 결과 |
| --- | --- | --- |
| | `파일경로:줄번호` / 실행한 명령 | 일치 / 불일치 / 확인 불가 |
